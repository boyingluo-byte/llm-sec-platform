## 0. 先讲清楚：为什么必须裁剪

七层纵深防御是**产品全景图**，完整落地需要企业基础设施（SSO/EDR/KMS/终端管理体系）、算法团队（RLHF 对齐）、多年运营数据积累（UEBA）。没有任何个人或小团队能把它全做出来——宣称能做全的简历，面试官一问就穿。

求职作品集的正确形态是**可运行的切片**：

> 选 3~4 层核心控制做深做透，做到可演示、可量化、可复现；其余层级明确标注演进路径，面试时讲「我知道全图，也做过落地，知道每个控制的成本和依赖」。

这个判断本身（能分清什么能做什么是运营负担）就是研发岗看重的能力。

**可落地性分三级**：
- ✅ **真能做**：MVP 范围内，有真实逻辑，可演示可量化
- ⚠️ **演示级**：做一条能跑通的端到端链路，不做完整体系
- 🏗 **路线图**：依赖企业基础设施/团队/数据积累，写明演进路径

## 1. 七层 × 可落地性分级明细

### 1.1 接入层

| 控制项 | 分级 | 落地方式 |
|---|---|---|
| API Key 认证 + 租户隔离 | ✅ | 网关 Bearer 鉴权，密钥哈希存储，多租户策略隔离 |
| RBAC/ABAC 简化分级权限 | ✅ | 策略表：租户 × 角色 → 可用模型/工具白名单，网关强制校验 |
| QPS/TPM 限流配额 | ✅ | Redis（或内存）令牌桶，按租户 × 模型多维计数 |
| SSO（OAuth2/SAML/LDAP） | 🏗 | 企业 IdP 依赖；MVP 用 API Key 演示等效链路，文档说明替换点 |
| 终端合规校验（EDR/VPN/IP 白名单） | 🏗 | 依赖企业终端体系，无法个人复现 |
| mTLS 双向认证 | ⚠️ | 本地自签证书跑通一条链路即可，不强制 |

### 1.2 输入层

| 控制项 | 分级 | 落地方式 |
|---|---|---|
| 直注检测（规则 + 语义双层） | ✅ | 规则 DSL（正则/关键词/编码还原）+ BERT 微调分类器 |
| **间接注入检测**（RAG 检索内容、工具返回值） | ✅ | **MVP 核心亮点**：所有进入上下文的不可信内容统一过检测引擎 |
| 系统提示词抽取检测 | ✅ | 规则层识别「输出你的系统提示」类话术 |
| 系统指令与用户输入硬隔离 | ✅ | 分容器存储 + 角色标记 + 输入长度/特殊字符策略 |
| 多轮上下文管控（轮次/窗口/PII 预脱敏） | ✅ | 窗口截断 + 历史内容脱敏占位符 |
| 多模态注入（图片/音频隐藏指令） | ⚠️ | 一条用例：带隐藏文字的图片 → OCR → 检测命中，证明链路 |
| 记忆/上下文投毒防护 | ⚠️ | mock 记忆存储 + 写入审核接口，演示「投毒→拦截」 |

### 1.3 模型层

| 控制项 | 分级 | 落地方式 |
|---|---|---|
| 越狱/对抗测试（可量化基线） | ✅ | 红队评测模块：用例库 + 判定 + 基线报告 |
| 模型权重完整性扫描（pickle 后门/safetensors 校验） | ✅ | **离线扫描工具**：反汇编检查 + 格式白名单，作为独立脚本交付 |
| 流式生成实时拦截 | ✅ | 网关 SSE chunk 级扫描，命中即截断 |
| 推理日志 TraceID 落盘 | ✅ | 全链路 request_id 贯穿，JSONL 审计 |
| 训练数据投毒检测 | ⚠️ | 一个离群点检测 demo（标注数据分布异常），不做完整体系 |
| RLHF/DPO 安全对齐 | 🏗 | 需算力 + 数据团队，简历上不碰 |
| 权重签名体系/仓库对接 | 🏗 | 需企业发布流水线 |

### 1.4 工具调用层

| 控制项 | 分级 | 落地方式 |
|---|---|---|
| 工具三级分级授权 | ✅ | 风险分级表 + 网关白名单校验 |
| 调用前双重校验（权限 + 业务规则） | ✅ | 第一重权限、第二重参数/范围校验（如工号范围、金额阈值） |
| 高危工具人工确认 | ✅ | 拦截后返回确认令牌，人工放行才放行 |
| **MCP 专项：工具描述注入扫描（tool poisoning）** | ✅ | **亮点**：静态扫描 MCP server 工具名/描述中的隐藏指令 |
| **MCP 专项：定义版本锁定（rug pull 防护）** | ✅ | 工具定义哈希固定，变更即告警并重新审核 |
| 单工具权限最小化（SELECT only/目录限制） | ✅ | 工具参数 schema 白名单校验 |
| 第三方插件沙箱 | ⚠️ | mock 工具本身即「沙箱外」边界演示；真实沙箱需容器基建 |
| Agent 目标劫持检测 | ⚠️ | 简化版：执行计划与原始目标的关键词/工具一致性校验 |

### 1.5 输出层

| 控制项 | 分级 | 落地方式 |
|---|---|---|
| DLP 敏感信息检测 + 脱敏替换 | ✅ | 正则 + NLP 实体识别，占位符替换，分级返回 |
| 违规内容二次拦截 | ✅ | 响应侧复用检测引擎 |
| 禁止输出系统提示/内部配置 | ✅ | 规则层 + 响应侧双重覆盖 |
| AIGC 内容标识 | ✅ | 响应头 + 元数据显式标识，对齐《AI 生成合成内容标识办法》 |
| 数字水印 | ⚠️ | 不可见字符水印 demo，证明溯源思路 |
| 高风险场景事实校验 | 🏗 | 依赖企业知识库比对体系 |
| 幻觉系统性治理 | 🏗 | 需业务反馈闭环积累 |

### 1.6 数据层

| 控制项 | 分级 | 落地方式 |
|---|---|---|
| 数据分类分级（标签 + 策略） | ⚠️ | 四级标签 + 策略表达成，演示「不同级别不同策略」 |
| 留存周期 + 到期自动清理 | ✅ | TTL 清理脚本 |
| 个人信息删除权（查询/删除接口） | ✅ | 数据删除 API + 审计留痕 |
| **RAG 知识库跨租户隔离** | ✅ | **亮点**：检索层强制 tenant 过滤 + 隔离测试用例 |
| 检索投毒防护（入库文档扫描） | ✅ | 文档入库过检测引擎（隐藏指令/零宽字符扫描） |
| 国密加密 + KMS 统一密钥 | 🏗 | 企业 KMS 依赖；MVP 用标准加密，文档写国产化替换路径 |
| 训练数据来源合规 | 🏗 | 需法务/采购流程 |

### 1.7 运营审计层

| 控制项 | 分级 | 落地方式 |
|---|---|---|
| 全链路审计日志 + TraceID | ✅ | JSONL 结构化审计，一键还原调用链 |
| 实时告警 + 紧急熔断 | ✅ | 高危行为规则触发 + 熔断开关（一键暂停租户/工具） |
| 简化事中干预（行为序列异常熔断） | ✅ | 工具调用序列模式匹配（如「查询→外传」立即中断） |
| 红队回归 + CI 门禁 | ✅ | 用例库进 CI，基线劣化即卡住发布 |
| 攻防演练（定期） | ✅ | 评测流水线即演练框架 |
| UEBA 内部滥用检测 | 🏗 | 需长期行为数据积累 |
| 威胁情报自动更新 | 🏗 | 需情报源对接 |

## 2. 裁剪结论：MVP 到底做什么

**统计**：✅ 真能做 17 项 · ⚠️ 演示级 6 项 · 🏗 路线图 7 项。

**MVP = 七层中的四层核心控制 + 一条评测贯穿线**（即项目方案文档已定义的范围）：

| 模块 | 覆盖的控制项 | 面试对应 |
|---|---|---|
| 安全管控网关 | 认证、分级权限、限流、高危工具拦截、熔断、审计 | JD 职责 3、4 |
| 检测引擎 | 直注 + 间接注入 + SP 抽取 + DLP + MCP 描述扫描 | JD 职责 1、2 |
| 红队评测 | 用例库、三层判定、金标准校准、基线报告、CI 门禁 | JD 职责 2、5 |
| RAG 靶场 | 知识库、投毒入口、mock 工具、跨租户隔离 | 攻击链演示载体 |

**明确不做**（写进路线图章节，面试主动讲）：SSO/EDR/mTLS、RLHF 对齐、UEBA、事实校验、国密 KMS、多 Agent 协同安全。每一项都注明「依赖什么、什么时候该做」——主动划边界比贪大求全更可信。

## 3. 为什么这个范围「真正做得出来」

三个硬事实，写在 README 和面试里：

1. **零 GPU 依赖**：核心链路（网关 + 规则引擎 + TF-IDF RAG + 评测）纯 CPU 可跑；vLLM/Qwen 靶机是可选增强，BERT 微调小数据量 CPU 几分钟完成
2. **零企业基础设施依赖**：不碰 SSO/EDR/KMS，API Key + 本地 Redis + JSONL 审计等效演示
3. **全部本地授权**：靶场自建，测试数据全假，合规红线天然满足——这也是它能「随便演示、随便开源」的原因

**8 周里程碑**（详见项目方案文档）：
W1 靶场（RAG + mock 工具）→ W2 网关 MVP → W3 检测规则层 → W4 模型微调 + ONNX → W5 评测闭环 + 基线报告 → W6 管控完善（权限/限流/MCP 扫描）→ W7 工程化（单测/压测/CI/Compose）→ W8 文档 + 面试叙事。
